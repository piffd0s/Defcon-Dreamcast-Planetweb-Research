# Dreamcast PlanetWeb Native DOOM Demo

This guide documents the files and host setup expected by `dreamcast_doom_native.py`. The launcher is macOS-specific and orchestrates a dedicated Flycast build, a DNS redirector, a rogue Eden HTTP service, and a POP3 server. It binds privileged ports, launches Flycast without GDB, stages the engine and WAD through the browser, plants the native loader stub, and triggers it when the prepared email is opened.

Use this only with systems, software, and network environments you own or are authorized to test.

## Direct file dependencies

The following paths are resolved relative to the directory containing `dreamcast_doom_native.py` unless noted otherwise.

| Path | Status | Purpose | Repo guidance |
| --- | --- | --- | --- |
| `dns_redirect.py` | Required | Redirects all guest DNS lookups to the host. | Include it. |
| `eden_mitm.py` | Required | Serves the PlanetWeb Eden chain and payload files. | Include it. |
| `mail_poc.py` | Required | Runs the POP3 service and constructs the MIME overflow email. | Include it. |
| `build/pwn_stagedoom.jar` | Required | Java stage executed through the Eden subscription flaw. Built from `src/org/junkyard/{StageDoom,Junk}.java` by `build_services_mac.sh`. | Generate locally or publish as a release artifact. |
| `build/doom.bin` | Required | Native SH-4 DOOM engine payload. Built in `native_doom/` and copied to `build/`. | Generate locally or publish as a release artifact. |
| `build/stub_native.bin` | Required | Native loader planted at `0x8C29ADE8`. Generated by `build_stage_native.py`, which imports `doom_full.py`. | Generate locally; it is coupled to the exact engine and WAD sizes. |
| `wad/doom1_trim.wad` | Required | Renderable game-data WAD staged with the engine. | Include only if you have distribution rights; otherwise document how the user supplies or generates it. |
| `emu/flycast-native/Flycast.app/Contents/MacOS/Flycast` | Required | Dedicated arm64 Flycast executable. The checked-out source is pinned at `d4fc0774107c4c307346b469499b9303a6ca0ffa` and has the two patches under `mac/patches/`. | Commit the patches and build instructions, not the local app bundle. The currently documented `picoppp` linger/reap change is not present in those patches and must be recovered or the claim removed. |
| Dreamcast PlanetWeb `.gdi` and every track named by it | Required, external path | Browser disc image. Defaults to a path under `~/Downloads`; override with `DISC`. | Do not commit unless you have distribution rights. The `.gdi` alone is insufficient—keep its referenced track files beside it. |
| `name_payload.hex` | Optional | Overrides the email payload generated from `MAIL_PC`. If present, its final four bytes must decode little-endian to `0x8C29ADE8`. | Usually omit it and let the launcher pass `MAIL_PC=8C29ADE8` to `mail_poc.py`. |

The executable checks the nine required entries above at startup. The three companion services use only the Python standard library. For the `stagedoom` route, `eden_mitm.py` additionally selects the four payload entries already listed (`pwn_stagedoom.jar`, `doom.bin`, `stub_native.bin`, and `doom1_trim.wad`). `mail_poc.py` optionally reads `mail_subject.txt`, `name_payload.hex`, and `doom_blob.txt`; none is required because it has built-in defaults and this launcher supplies the return address through the environment. `www/`, fuzz corpora, and the other chain JARs are not dependencies of this route.

### Filename discrepancy resolved

The launcher requires `build/stub_native.bin`; its docstring and status output now use that filename consistently. `build/stub.bin` belongs to a different demo.

### Stub/WAD coupling

`build_stage_native.py` bakes the byte sizes of `build/doom.bin` and the selected WAD into the loader stub. Its historical default is `wad/doom_e1m1.wad`, but this launcher and the `stagedoom` Eden route serve `wad/doom1_trim.wad`. Rebuild the required stub with the explicit override:

```bash
NATIVE_WAD=wad/doom1_trim.wad python3 build_stage_native.py
```

Re-run that command whenever either payload changes. Using the script's default produces a valid-looking but incompatible `stub_native.bin`.

## Runtime state and configuration

These paths are not in the launcher's startup check, but they matter for a reproducible demo:

| Path | Role |
| --- | --- |
| `emu/fchome/` | Isolated `HOME` used when Flycast is launched. |
| `emu/fchome/.flycast/data/` | Flycast log, firmware/NVRAM, VMU saves, configuration, and temporary save states. |
| `emu/flash_baseline/` | Clean copies restored before each launch. Created automatically from files already present in Flycast's data directory. |

The launcher recognizes these persistent files when present:

- `dc_nvmem.bin`
- `dc_flash.bin`
- `T31901N_vmu_save_A1.bin`
- `vmu_save_A2.bin`

For a public repository, commit only sanitized state you are legally permitted to distribute. Do not publish firmware, personal mail settings, credentials, cookies, or unique console data. A safer repository contains setup instructions or a provisioning script and keeps local state ignored.

The repository-root `.gitignore` excludes this mutable state along with firmware, disc images, generated products, local toolchains, and commercial WADs. In particular, it includes:

```gitignore
emu/fchome/
emu/flash_baseline/
*.state
*.log
__pycache__/
*.py[cod]
```

If the demo relies on a carefully preconfigured, sanitized browser flash/VMU baseline, store it as a separately controlled demo artifact rather than assuming a fresh checkout has it.

```text
.

├── dns_redirect.py
├── eden_mitm.py
├── mail_poc.py
├── DREAMCAST_DOOM_NATIVE_HOWTO.md
├── build/
│   ├── pwn_stagedoom.jar
│   ├── doom.bin
│   └── stub_native.bin
├── src/                         # recommended: sources for the three build artifacts
├── patches/
│   └── flycast-picoppp-reap.patch
├── emu/
│   ├── flycast-native/
│   │   └── Flycast.app/
│   ├── fchome/                  # normally local/ignored
│   └── flash_baseline/          # normally local/ignored
└── wad/
    └── doom1_trim.wad
```

Also include the script or exact commands that produce `pwn_stagedoom.jar`, `doom.bin`, and `stub_native.bin`. `doom1_trim.wad` must be supplied from a legally obtained compatible WAD; it is intentionally ignored. Committing only opaque binaries makes the demo difficult to review or reproduce.

`src-build/flycast-src/` is a disposable emulator checkout and is excluded by the root `.gitignore`. `native_doom/doomgeneric/` is intentionally registered as a submodule of `https://github.com/ozkl/doomgeneric.git`; clone this repository recursively or run `git submodule update --init` before building the native engine. Then apply the checked-in low-memory/no-audio port changes:

```bash
git -C native_doom/doomgeneric apply ../patches/01-dreamcast-low-memory-no-audio.patch
```

## Host requirements

- macOS. The launcher depends on a `.app` bundle and the macOS commands `defaults`, `ipconfig`, `ifconfig`, `route`, `stat`, and `caffeinate`.
- Python 3. The launcher itself uses only the standard library, so it does not need a `requirements.txt`.
- Root privileges to bind TCP/UDP port 53, TCP port 80, and TCP port 110.
- A dedicated Flycast build at the exact path shown above, produced from the pinned source and checked-in patches described above.
- A configured isolated Flycast home with any required firmware and PlanetWeb network/mail settings.
- A host interface reachable from the emulated Dreamcast network.
- Ports 53, 80, and 110 free before launch.

The companion Python services use only the standard library. Their route-specific optional files are covered in the dependency audit above.

## Initial setup

1. Place `dreamcast_doom_native.py` at the repository root with the three companion Python services.

2. Build or obtain the three payload artifacts and place them at their exact paths:

   ```text
   build/pwn_stagedoom.jar
   build/doom.bin
   build/stub_native.bin
   ```

3. Supply `wad/doom1_trim.wad`. Confirm that the engine-compatible WAD contains the assets the script comments call out, including `TITLEPIC` and sprites.

4. Build the dedicated Flycast copy with `mac/build_flycast.sh`, which pins/reuses the source checkout, applies `mac/patches/01-macos-cmake-ninja.patch` and `mac/patches/02-doomdbg-fault-dump.patch`, builds the `Flycast` target, and signs the macOS app. Install or copy it as:

   ```text
   emu/flycast-native/Flycast.app
   ```

   Keep this copy separate from the stock Flycast instance used by the GDB and calculator demos. Before claiming the Java staging route has a `picoppp` connection-reap fix, add that missing patch to `mac/patches/` and the build recipe.

5. Create and configure the isolated Flycast home at `emu/fchome`. Launch the dedicated build against that home long enough to configure the browser's emulated network and POP3 account. The launcher expects the browser to contact Eden when it goes online and the mail client to retrieve from the host POP3 service.

6. Shut Flycast down cleanly. On the first scripted run, the launcher copies recognized flash/VMU files from `emu/fchome/.flycast/data/` into `emu/flash_baseline/`. Start from a known-good, sanitized configuration.

7. Keep the PlanetWeb `.gdi` and all tracks referenced by it together outside the repository. The default location is:

   ```text
   ~/Downloads/Internet Browser V3.0 for Dreamcast (USA)/
   ```

   A different location can be supplied with `DISC`.

8. Do not create `name_payload.hex` unless you intentionally need a fixed payload. If it exists, verify that its last four bytes represent `0x8C29ADE8` in little-endian order.

## Preflight checks

From the repository root:

```bash
python3 -m py_compile dreamcast_doom_native.py dns_redirect.py eden_mitm.py mail_poc.py

test -x emu/flycast-native/Flycast.app/Contents/MacOS/Flycast
test -f build/pwn_stagedoom.jar
test -f build/doom.bin
test -f build/stub_native.bin
test -f wad/doom1_trim.wad

# Verify that the size-baked stub was rebuilt for the WAD this route serves.
NATIVE_WAD=wad/doom1_trim.wad python3 build_stage_native.py

sudo lsof -nP -iUDP:53 -iTCP:53 -iTCP:80 -iTCP:110
```

The final command should not show an unrelated listener on a required port. The launcher attempts to stop stale copies of its own services and any process named `Flycast`, but it will not resolve every possible port conflict.

## Run the demo

When automatic host-IP detection and the default disc path are correct:

```bash
sudo python3 dreamcast_doom_native.py
```

For an explicit disc and host address, pass them through `sudo` deliberately:

```bash
sudo env \
  DISC="/absolute/path/to/Internet Browser V3.0 for Dreamcast (USA).gdi" \
  HOST_IP="192.0.0.2" \
  python3 dreamcast_doom_native.py
```

Using `sudo env` avoids relying on whether the local `sudo` configuration preserves shell environment variables.

The launcher then:

1. Stops stale demo services and Flycast processes.
2. Restores the clean flash/VMU baseline.
3. Starts `caffeinate` to keep the Mac awake.
4. Starts DNS redirection, Eden HTTP, and POP3 services.
5. Starts Flycast with networking enabled and the GDB server disabled.

Inside PlanetWeb:

1. Use `A` three times, choose **Start**, and enter the web browser.
2. Let the browser connect. Do not navigate elsewhere and do not open Mail yet.
3. Watch the terminal as the Eden chain serves the JAR, engine, WAD, and loader stub.
4. Wait for the terminal to print `ARMED`.
5. Open **Mail**, choose **Check Mail**, and open the `DOOM-STAGE` message promptly.

Opening the message before `ARMED` can make the saved-return-address jump occur before the loader is planted.

Press `Ctrl-C` to stop the DNS, Eden, POP3, and Flycast processes and restore the terminal state.

## Environment variables

| Variable | Meaning |
| --- | --- |
| `DISC` | Absolute path to the PlanetWeb `.gdi`. |
| `HOST_IP` | Host IPv4 address reachable by the emulated guest; use this when auto-detection is wrong. |
| `RECAPTURE=1` | Replaces the current flash/VMU baseline with recognized files from the configured Flycast data directory. Use only after confirming the current state is clean and correct. |

`MAIL_PC` and `MAIL_PAD` are set internally for `mail_poc.py` to `8C29ADE8` and `64`; they are not intended as normal operator overrides in this launcher.

## Logs

| Path | Contents |
| --- | --- |
| `/tmp/demo_dns.log` | DNS redirector output. |
| `/tmp/eden_native.log` | Eden requests, payload streaming, chunk progress, and heap-stage confirmation. |
| `/tmp/mail_native.log` | POP3 activity, including `RETR` or `TOP`. |
| `emu/fchome/.flycast/data/flycast.log` | Flycast boot and emulator log. |

These files are overwritten at service launch or Flycast boot.

## Troubleshooting

### `missing required file`

Use the path printed by the launcher. Remember that the actual stub filename is `build/stub_native.bin`, not `build/stub.bin`.

### `HOST_IP resolved to loopback`

The guest cannot reach `127.0.0.1`. Rerun with a reachable interface address:

```bash
sudo env HOST_IP="192.0.0.2" DISC="/absolute/path/browser.gdi" \
  python3 dreamcast_doom_native.py
```

### A server cannot bind its port

Check for other DNS, HTTP, or POP3 listeners:

```bash
sudo lsof -nP -iUDP:53 -iTCP:53 -iTCP:80 -iTCP:110
```

Stop or reconfigure the conflicting service. The port constants are fixed in the launcher and must also agree with the guest configuration and companion services.

### The browser connects but the chain never arms

- Inspect `/tmp/eden_native.log` and `/tmp/demo_dns.log`.
- Confirm the guest is using `HOST_IP` for DNS.
- Confirm `eden_mitm.py --chain stagedoom` recognizes and serves the expected paths.
- Keep the host awake and Flycast in the foreground while the multi-megabyte staging stream completes.
- Verify that the dedicated Flycast build is being launched. If reliable Java staging depends on a `picoppp` linger/reap change, recover and add that patch first; it is not in the current `mac/patches/` set.

### `name_payload.hex targets ... not the stub`

Delete `name_payload.hex` so `MAIL_PC=8C29ADE8` is used, or regenerate it with the correct little-endian saved-return-address value.

### Flycast repeatedly reports the RAM-reservation race

The launcher retries up to 12 times when `flycast.log` contains `Verify Failed`. Inspect `emu/fchome/.flycast/data/flycast.log` if all retries fail.

### The email is fetched but DOOM does not start

- Confirm that the terminal printed `ARMED` before the message was opened.
- Check `/tmp/mail_native.log` for `RETR` or `TOP`.
- Re-stage the payload, then reopen the message promptly; the staged blob resides in the JVM heap and can be overwritten by later browser activity.
- Confirm that `build/stub_native.bin` was built for the exact engine/WAD combination being served.

## Completing the dependency audit

Once the companion scripts and source tree are present, use this from the repository root to find likely transitive files and external commands:

```bash
rg -n \
  '^(from|import) |open\(|Path\(|os\.path|subprocess|Popen|check_output|\.jar|\.bin|\.wad|\.conf|\.patch' \
  dreamcast_doom_native.py dns_redirect.py eden_mitm.py mail_poc.py src patches
```

Review dynamic paths and server route handlers manually. In particular, verify which files `eden_mitm.py` serves for `--chain stagedoom` and whether `mail_poc.py` loads templates or payload files beyond the optional `name_payload.hex`.
